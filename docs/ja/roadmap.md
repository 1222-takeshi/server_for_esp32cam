# 将来の開発 / ロードマップ

このプロジェクトは現在初期段階にあり、単一クライアントからの基本的な画像アップロードに焦点を当てています。長期的なビジョンには、これを高度な機能を備えた包括的なマルチカメラ管理システムに進化させることが含まれます。将来の開発で計画されている主な分野は次のとおりです:

### 1. 強化されたマルチカメラサポート:

*   **カメラ識別と管理:**
    *   各ESP32-CAMクライアントを一意に識別するためのシステムを実装します (例: MACアドレス、設定可能なID)。
    *   複数の識別されたカメラからのストリーム/画像を処理および区別するためのサーバーサイドロジック。
*   **動的Webインターフェース:**
    *   複数のカメラからのフィードを同時に表示できるWeb UIを開発します (例: グリッドビュー、選択可能なフィード)。
    *   ユーザーが個々のカメラフィードにラベルを付けたり名前を付けたりできるようにします。
*   **スケーラブルなストレージ:**
    *   保存された画像を特定のカメラに簡単に帰属できる方法で整理します (例: カメラIDごとのサブディレクトリ)。

### 2. 機械学習統合:

*   **サーバーサイドの物体検出/認識:**
    *   基本的な画像処理タスク (例: モーション検出、顔検出) のためにOpenCVを統合します。
    *   物体認識 (例: 一般的な物体、人物、特定のアイテムの識別) のために、事前学習済みまたはカスタムモデルを使用して、より高度なMLフレームワーク (TensorFlow, PyTorch) の使用を検討します。
    *   受信した画像/ストリームを処理し、結果を保存/表示するためのパイプラインを開発します。
*   **リアルタイムアラートと通知:**
    *   ML検出結果に基づいて、特定のイベントに対するアラート (例: メール、Web通知) を送信するシステムを実装します。
*   **データ注釈とトレーニング (長期):**
    *   カスタムMLモデルをトレーニングするために画像を収集および注釈付けする機能を検討します。

### 3. リモートI/O制御とセンサー統合:

*   **双方向通信:**
    *   サーバーからESP32クライアントにコマンドを送信するための堅牢な通信チャネル (例: MQTT、WebSockets、または専用HTTPエンドポイント) を確立します。
*   **モーター制御インターフェース:**
    *   接続されたESP32デバイスでモーターの動きをトリガーするためのサーバーサイドUI要素とAPIエンドポイントを開発します (例: パンチルトカメラマウント、ロボットコンポーネント)。
    *   コマンドを解釈し、モーターを作動させるためのESP32ファームウェア (例: PWM、モータードライバー経由)。
*   **センサーデータ収集:**
    *   ESP32クライアントがセンサーデータ (例: 温度、湿度、モーションセンサー) をサーバーに送信できるようにします。
    *   カメラフィードと並べて、またはダッシュボードにセンサーデータを表示します。

### 4. システム改善:

*   **セキュリティ:** ユーザー認証、安全な通信 (HTTPS)、およびフィードや制御機能へのアクセスに対する承認を実装します。
*   **設定:** UIまたは設定ファイル (例: カメラ設定、ストレージパス、MLモデル選択) を介してより多くの設定を構成できるようにします。
*   **パフォーマンスとスケーラビリティ:** 複数の同時ストリームと大量のデータを処理するためにサーバーのパフォーマンスを最適化します。
*   **ユーザーインターフェース/ユーザーエクスペリエンス:** 情報の使いやすさと表示を向上させるためにWebインターフェースを継続的に改善します。
*   **包括的なAPI:** サーバーとのプログラムによる対話のための十分に文書化されたAPIを開発します。
