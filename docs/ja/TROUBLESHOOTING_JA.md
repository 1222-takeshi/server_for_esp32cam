# トラブルシューティングガイド

このガイドでは、ESP32マルチカメラシステムの設定または実行中に発生する可能性のある一般的な問題と、その解決策およびデバッグのヒントをリストアップしています。

## サーバーサイドの問題:

*   **問題:** サーバーが起動しない、または `ImportError: No module named flask`。
    *   **解決策:** Python環境にFlaskがインストールされていることを確認してください。仮想環境を使用している場合（[セットアップガイド](SETUP_JA.md)で推奨）、それがアクティブになっていることを確認してください。`pip install Flask` を実行します。

*   **問題:** `OSError: [Errno 98] Address already in use` (または類似のエラー)。
    *   **解決策:** ポート8080が他のアプリケーションによって既に使用されています。
        *   ポートを使用している他のアプリケーションを停止します。
        *   または、`server.py` を変更して別のポートを使用します: `app.run(host='0.0.0.0', port=8080)` を `app.run(host='0.0.0.0', port=<new_port_number>)` に変更し、クライアントサイドも同様に更新します。

*   **問題:** サーバーは実行されていますが、クライアント (例: ESP32-CAM) が接続できません。
    *   **確認事項:**
        *   **ファイアウォール:** サーバーマシンのファイアウォールがポート8080 (または使用しているポート) への着信接続をブロックしていないことを確認してください。
        *   **IPアドレス:** クライアントの設定でサーバーマシンの正しいIPアドレスを使用していることを確認してください。クライアントが別のデバイスの場合は、サーバーのローカルネットワークIP (例: `192.168.1.x`) を使用し、`127.0.0.1` や `localhost` は使用しないでください。
        *   **ネットワーク:** サーバーとクライアントが同じWi-Fiネットワーク上にあることを確認してください。
        *   **サーバーログ:** クライアントが接続またはアップロードを試みたときに、`server.py` のコンソール出力にエラーメッセージがないか確認してください。

*   **問題:** ファイルはアップロードされますが、画像が破損しているか、期待したものではありません。
    *   **確認事項:**
        *   **クライアントサイドのコード:** クライアントが画像データを正しく送信していることを確認してください (例: 正しい画像形式、完全なデータ)。
        *   **Content-Type ヘッダー:** 現在の `server.py` は保存のために `Content-Type` を厳密には強制しませんが、クライアントが適切なヘッダー (例: `image/jpeg`) を送信していることを確認してください (これは良い習慣です)。サーバーは生のボディを保存するため、クライアントは有効な画像データを送信する必要があります。
        *   **ファイル命名/保存:** サーバーはファイルを `image_<timestamp>.jpg` として保存します。クライアントがJPEG以外のデータを送信した場合でも、ファイル拡張子は `.jpg` になりますが、内容は正しくない可能性があります。

*   **問題:** `uploads` ディレクトリが見つからない、または権限の問題。
    *   **解決策:** `server.py` スクリプトは `uploads` ディレクトリが存在しない場合に作成しようとします。権限のために失敗する場合は、プロジェクトのルートフォルダに手動で `uploads` ディレクトリを作成し、スクリプトを実行しているユーザーが書き込み権限を持っていることを確認してください。

## クライアントサイドの問題 (ESP32-CAMの例):

*   **問題:** ESP32-CAMがWi-Fiに接続できません。
    *   **確認事項:**
        *   **認証情報:** ESP32-CAMスケッチ内のWi-Fi SSIDとパスワードを再確認してください。
        *   **信号強度:** ESP32-CAMが良好なWi-Fi信号を受信していることを確認してください。
        *   **ルーター設定:** 一部のルーターには、新しいデバイスの接続を妨げるMACフィルタリングやその他のセキュリティ設定がある場合があります。

*   **問題:** ESP32-CAMはWi-Fiに接続しますが、サーバーへの画像の送信に失敗します。
    *   **確認事項:**
        *   **サーバーIPとポート:** ESP32-CAMスケッチ内のサーバーIPアドレスとポートが正しく、実行中のサーバーと一致していることを確認してください。
        *   **HTTP POSTリクエスト形式:** スケッチがHTTP POSTリクエストを正しく作成していることを確認してください (正しいエンドポイント `/upload`、正しいヘッダー、ボディ内の画像データ)。
        *   **シリアルモニター:** Arduino IDEのシリアルモニターを使用して、ESP32-CAMスケッチからのエラーメッセージやデバッグ出力を確認してください。これはクライアントサイドの問題を診断するために不可欠です。
        *   **サーバーログ:** ESP32-CAMがアップロードを試みたときに、`server.py` のコンソール出力にメッセージがないか同時に確認してください。

*   **問題:** ESP32-CAMでの画像キャプチャが失敗します。
    *   **確認事項:**
        *   **カメラモデル:** ESP32-CAMスケッチで正しいカメラモデルが選択されていることを確認してください (例: `CAMERA_MODEL_AI_THINKER`)。[セットアップガイド](SETUP_JA.md#クライアントサイドのセットアップ-例-arduino-ideを使用したesp32-cam)でボードの選択を参照してください。
        *   **カメラ接続:** カメラモジュールがESP32ボードに正しく接続されていることを確認してください。
        *   **電源:** ESP32-CAMは、特にWi-Fiがアクティブな場合、電力を大量に消費する可能性があります。安定した十分な電源が供給されていることを確認してください (例: 5V、一部のセットアップでは最低2Aを推奨)。電力不足はクラッシュやブラウンアウトを引き起こす可能性があります。
        *   **GPIOピン:** カメラやSDカードに特定のGPIOが必要なボードを使用している場合は、それらが正しく設定され、競合していないことを確認してください。

*   **公式リソースの参照:** ESP32カメラドライバ、カメラの初期化、またはカメラコンポーネントからの特定のエラーコードに関連する問題については、[公式esp32-cameraリポジトリのissues](https://github.com/espressif/esp32-camera/issues)およびドキュメントを確認してください。これは[セットアップガイド](SETUP_JA.md#公式esp32カメラドキュメントの参照)でも言及されています。

## 一般的なヒント:

*   **シンプルに始める:** 問題が発生した場合は、問題を切り分けてみてください。まず `curl` や Postman のようなツールでサーバーの機能をテストします。次に、クライアントのWi-Fi接続を個別にテストします。
*   **ログの確認:** 常に `server.py` のコンソール出力とクライアントデバイス (該当する場合) のシリアルモニター出力を確認してエラーメッセージを探してください。
*   **段階的な開発:** クライアントコード (ESP32-CAM用など) を記述する際は、機能を段階的に追加してください (Wi-Fiに接続し、次に簡単なGETリクエストを試し、次にデータをPOSTしてみるなど)。
