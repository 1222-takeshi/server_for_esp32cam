# コントリビューション

このプロジェクトへのコントリビューションを歓迎します！コントリビュートしたい場合は、以下の一般的なガイドラインに従ってください:

1.  **リポジトリのフォーク:**
    まず、メインリポジトリを自分のGitHubアカウントにフォークします。

2.  **ブランチの作成:**
    フォークしたリポジトリに、機能追加またはバグ修正用の新しいブランチを作成します。説明的なブランチ名を使用してください (例: `feat/add-image-filtering` または `fix/upload-error-handling`)。
    ```bash
    git checkout -b feat/your-new-feature
    ```

3.  **変更の実施:**
    機能またはバグ修正を実装します。
    *   コードが既存のスタイルと構造に従っていることを確認してください。
    *   新しい機能を追加する場合は、関連するドキュメントや例を追加することを検討してください。
    *   `pyproject.toml` のPython依存関係を追加・変更した場合は、固定済みロックファイルを再生成してください: `uv pip compile pyproject.toml --extra dev --extra server --extra ml --extra onnx --extra capture --generate-hashes --python-platform x86_64-unknown-linux-gnu -o requirements.lock.txt`（このplatform指定は、CIの`dependency-audit`ジョブが`ubuntu-latest`上でこのロックファイルをインストールする環境に合わせたものです。Linux以外のホストで指定を省略すると、実際にインストール可能なものと一致しないハッシュが生成される場合があります）。`pyproject.toml`で既に許容されている範囲内で新しいバージョンを取り込みたい場合は`--upgrade`を追加してください。

4.  **変更のテスト:**
    変更が期待どおりに機能し、新しい問題が発生しないことを確認するために、変更を徹底的にテストしてください。
    *   該当する場合は、新しい機能の単体テストを作成してください。

5.  **変更のコミット:**
    明確で簡潔なコミットメッセージで変更をコミットします。
    ```bash
    git add .
    git commit -m "feat: Add feature X"
    # または "fix: Resolve bug Y"
    ```

6.  **フォークへのプッシュ:**
    変更をフォークしたリポジトリにプッシュします。
    ```bash
    git push origin feat/your-new-feature
    ```

7.  **プルリクエストのオープン:**
    元のリポジトリに移動し、フォークしたブランチから元のリポジトリの `main` ブランチへのプルリクエスト (PR) をオープンします。
    *   PRに変更の明確な説明を記載してください。
    *   関連するissueを参照してください (例: "Closes #123")。

8.  **コードレビュー:**
    PRがレビューされ、フィードバックが提供される場合があります。要求された場合は、さらなる変更を行う準備をしてください。

コントリビュートすることにより、あなたのコントリビューションがプロジェクトのライセンスの下でライセンスされることに同意するものとします。
