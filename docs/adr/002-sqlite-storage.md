# ADR-002: SQLite をメタデータストアとして採用

- **日付**: 2024-01-01
- **ステータス**: 採用

## コンテキスト

スナップショットのメタデータ（カメラ ID・撮影時刻・ファイルパス・検知結果など）を永続化するデータストアを選定する必要があった。
Raspberry Pi 上でシングルプロセスで動作し、運用コストを最小にすることが制約。

## 決定

SQLite をメタデータの永続化ストアとして採用する。

## 理由

- 外部サービス不要でゼロ設定運用ができる
- Raspberry Pi のような低スペック機でも十分なパフォーマンスを発揮する
- Python 標準ライブラリに組み込まれており追加インストール不要
- WAL モードにより並行読み取りと書き込みを両立できる
- バックアップが単一ファイルのコピーで完結する

## 却下した代替案

| 代替案 | 却下した理由 |
|--------|------------|
| PostgreSQL | 別プロセスが必要。Raspberry Pi での運用コストが高い |
| MySQL / MariaDB | 同上 |
| JSON ファイル | クエリ・インデックスが使えない。並行書き込みで破損リスク |
| Redis | 揮発性。永続化設定が必要で複雑さが増す |

## 結果・影響

- マルチプロセスデプロイ（Gunicorn 複数ワーカー）では書き込み競合リスクがある。シングルプロセス前提
- DB ファイルをボリュームマウントして永続化する必要がある
- スキーマ変更は起動時の Python マイグレーションで自動適用される
