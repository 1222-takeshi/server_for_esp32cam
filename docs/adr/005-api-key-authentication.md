# ADR-005: API キー + Bearer トークンによる認証方式

- **日付**: 2024-09-01
- **ステータス**: 採用

## コンテキスト

デバイス（ESP32-CAM）からのアップロードと、管理者によるカメラ管理 API の両方を保護する認証方式が必要になった。
デバイスは Arduino SDK で動作するため、複雑な認証フロー（OAuth 等）は実装困難。

## 決定

- **デバイス向け**: `X-API-Key` ヘッダーに事前共有キー (`DEVICE_API_KEY`) を付与する
- **管理者向け**: `Authorization: Bearer <token>` に管理者トークン (`ADMIN_TOKEN`) を付与する

## 理由

- Arduino SDK は `HTTPClient.addHeader()` で任意ヘッダーを追加できる
- 事前共有キーは設定が簡単で、デバイスファームウェアへの組み込みが容易
- 管理者 API は Bearer トークンで分離することで、デバイスキーが漏洩しても管理操作は保護される
- 未設定（空文字）の場合は認証を無効化し、ローカル開発の摩擦を減らす

## 却下した代替案

| 代替案 | 却下した理由 |
|--------|------------|
| JWT | 鍵管理・有効期限処理が必要。Arduino SDK での実装コストが高い |
| OAuth 2.0 | デバイス向けには過剰。認可サーバーが別途必要 |
| Basic 認証 | Base64 は暗号化でない。HTTPS なし環境でのリスクが高い |
| TLS クライアント証明書 | ESP32 での証明書管理コストが高い |

## 結果・影響

- API キーがログや URL に混入しないよう運用ルールが必要（セクリット管理）
- DEVICE_API_KEY と ADMIN_TOKEN はそれぞれ 32 バイト以上のランダム値を推奨
- インターネット公開時は HTTPS が必須（平文通信では API キーが傍受される）
