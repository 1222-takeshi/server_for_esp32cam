# ADR-001: HTTP アップロードプロトコルの採用

- **日付**: 2024-01-01
- **ステータス**: 採用

## コンテキスト

ESP32-CAM で JPEG スナップショットをサーバーに送信する手段を選定する必要があった。
デバイスは Arduino SDK で動作し、Wi-Fi 経由でサーバーと通信する。
深いスリープからの復帰後に単一フレームを送信するユースケースが主である。

## 決定

`POST /upload` エンドポイントへの HTTP multipart/form-data または raw バイナリ送信を採用する。

## 理由

- ESP32 の Arduino SDK には安定した HTTP クライアントライブラリが存在する
- 1 フレームのアップロードに TCP 接続の維持が不要であり、深いスリープ運用と相性がよい
- デバッグ・テストが `curl` 一発でできる

## 却下した代替案

| 代替案 | 却下した理由 |
|--------|------------|
| MQTT | ブローカーが別途必要。シンプルな画像転送にはオーバーエンジニアリング |
| FTP | セキュリティ・認証が弱い。Arduino ライブラリの品質が不安定 |
| WebSocket のみ | 接続維持コストが高く、深いスリープ運用に不向き |

## 結果・影響

- HTTP エンドポイントは `Content-Type: image/jpeg` または `multipart/form-data` のどちらも受け付ける
- デバイスが多くなると HTTP の状態管理コストが増える（各リクエストが独立）
- WebSocket は後から連続アップロード用途として追加（ADR-004 参照）
