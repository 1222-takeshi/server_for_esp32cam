# ADR-004: WebSocket によるリアルタイムアップロード追加

- **日付**: 2024-06-01
- **ステータス**: 採用

## コンテキスト

HTTP アップロード (ADR-001) は深いスリープ運用に最適だが、連続撮影・リアルタイム監視のユースケースでは
毎フレームの TCP ハンドシェイクコストが問題になることが判明した。
また、アップロード完了をダッシュボードにリアルタイム反映したいという要求が発生した。

## 決定

WebSocket エンドポイント (`/upload/ws`) を追加し、バイナリフレームとして JPEG を受信する。

## 理由

- 1 接続の確立で複数フレームを送信でき、TCP オーバーヘッドを削減できる
- サーバーからクライアント（ブラウザ）へのプッシュ通知に同じ接続を流用できる
- HTTP アップロードを廃止せず、用途に応じて使い分けができる

## 却下した代替案

| 代替案 | 却下した理由 |
|--------|------------|
| Server-Sent Events (SSE) | 単方向のみ。デバイスからのアップロードには使えない |
| HTTP ストリーミング | 中間プロキシでバッファリングされるリスクがある |

## 結果・影響

- WebSocket 接続数が増えるとメモリ消費が増加する。`MAX_WS_CONNECTIONS` で上限を設ける
- フレームレートを制限しないと帯域・CPU を占有する。`UPLOAD_WS_MIN_FRAME_INTERVAL_SECONDS` で対策
- HTTP アップロードと WebSocket アップロードの両方を維持するため、テストカバレッジが増える
