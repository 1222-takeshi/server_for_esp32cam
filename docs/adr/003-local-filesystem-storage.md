# ADR-003: ローカルファイルシステムを画像ストレージとして採用

- **日付**: 2024-01-01
- **ステータス**: 採用

## コンテキスト

JPEG スナップショット画像ファイルの保存先を選定する必要があった。
メタデータ (ADR-002) とは別に、バイナリファイルの保存場所を決める。

## 決定

ローカルファイルシステムを唯一の画像ストレージバックエンドとして採用する。

## 理由

- セットアップが最もシンプル（追加サービス不要）
- Raspberry Pi の SD カードや USB ストレージに直接書き込める
- Docker named volume でコンテナ外に永続化できる
- ストレージ保全戦略（保存期間・容量上限）をサーバー側で制御できる

## 却下した代替案

| 代替案 | 却下した理由 |
|--------|------------|
| Google Drive API | 認証設定が複雑。オフライン環境や Raspberry Pi での設定コストが高い |
| S3 / オブジェクトストレージ | クラウド依存。コストとオフライン耐性の懸念 |
| NAS (SMB/NFS) | ネットワーク障害時に書き込み不能になる。優先度が低いと判断 |

## 結果・影響

- 複数サーバーインスタンスでのファイル共有はできない（スケールアウト不可）
- ボリュームが枯渇すると書き込みが失敗する。`STORAGE_RETENTION_MAX_BYTES` と `MAX_AGE_SECONDS` で管理する
- 将来のバックエンド切り替えに備え、ストレージ操作は `script/storage.py` に抽象化されている
