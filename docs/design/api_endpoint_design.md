# APIエンドポイント設計ドキュメント

## 1. プロジェクトの技術スタック

- **言語:** Python
- **フレームワーク:** Flask

## 2. 画像データ受け取りAPIエンドポイントの仕様

ESP32-CAMから画像データを受け取るためのAPIエンドポイントの仕様は以下の通りです。

- **エンドポイントのURL:** `/upload`
    - シンプルさを優先し、ルートパス直下の `/upload` とします。将来的にバージョン管理が必要になった際には `/api/v1/upload` などに変更することを検討します。
- **HTTPメソッド:** `POST`
    - 画像をサーバーに送信（作成）するため、`POST` メソッドが適切です。
- **リクエストボディの形式:** raw JPEG binary
    - スナップショット経路を単純に保つため、リクエストボディには JPEG バイト列そのものを送ります。
- **必須ヘッダ:** `Content-Type: image/jpeg`, `X-Device-Id`, `X-Captured-At`
    - `X-Device-Id` は送信元カメラの識別子です。
    - `X-Captured-At` は timezone 付き ISO 8601 で送る撮影時刻です。

## 3. 受け取った画像の処理・保存方針

受け取った画像の処理と保存について、以下の基本方針を決定します。

- **処理:**
    - 受信した画像データは、一時的にメモリに読み込み、基本的なバリデーション（ファイルサイズ、形式など）を行います。
    - 現時点では、画像のリサイズや圧縮などの前処理は行わず、シンプルに保存することを優先します。必要に応じて将来的に追加を検討します。
- **保存:**
    - サーバー上の特定のディレクトリ（例: `uploads/`）に保存します。このディレクトリは、サーバーアプリケーションの起動時に存在しない場合は作成するようにします。
    - ファイル名は、タイムスタンプ（例: `YYYYMMDD_HHMMSS.jpg`）やユニークなIDを付与することで、重複を避け、管理しやすくします。
    - 最新の画像は、タイムスタンプやユニークなIDを付与したファイル名で保存し、最新画像へのアクセスはシンボリックリンクやデータベース参照を通じて行うことを検討します。これにより、過去の画像履歴を保持しつつ、常に最新の画像を参照できるようになります。
