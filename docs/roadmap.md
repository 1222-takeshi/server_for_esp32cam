Core M1–M3 capabilities and the M4 evaluation tool have landed; acceptance still depends on the seven-day, recovery-time, and labeled-cat checks above. Device deployment is coordinated sequentially. Every PR needs meaningful tests, static checks, CI validation, and at least two read-only reviews; unresolved BLOCKING/IMPORTANT findings prevent merge.

For M1, reloading the Pi UI in Safari showed 989 saved snapshots, latest saved at 16:48:45 JST with one detection, the no-target retention explanation, a separate live image updating about every five seconds, and healthy/ready status. The saved count and latest timestamp matched the API. This final UI check was completed on 2026-10-11 at 18:14 JST.

Seven-day observation started on 2026-10-11 12:02:49 JST. The result timer is scheduled for 2026-10-18 12:03 JST; tool completion and sample ratios do not establish time uptime. Public-image comparisons do not establish own-cat or lights-off accuracy; real-site labeled images are still required. Record acceptance thresholds before measurement and preserve baselines.

The isolated capture, freshness, and bounded inference path passed the Raspberry Pi-only minimum 5 Hz technical test; the previous Mac-based acceptance remains withdrawn. The same YOLO11n FP32 ONNX 320 model, threshold 0.5 and QVGA/JPEG12 settings were retained. Public-fixture thread parity is not field precision/recall. Next work covers production integration and simultaneous load, labeled own-cat/day/lights-off evaluation, further Pi inference optimization toward 10 Hz, calibration and motor-free angle simulation. Tracker interpolation does not count as recognition. [#486](https://github.com/1222-takeshi/server_for_esp32cam/issues/486) stays open; motor actuation requires both the rate/freshness checks and the existing [cat-following safety contract](design/cat-following-capability.md).

The experimental firmware interrupted normal camera-to-Pi image updates from 2026-10-16 23:25:22 UTC; the work paused and resumed at 2026-10-17 06:19 UTC. The first rollback OTA failed during transfer; the second succeeded. Original five-second/QVGA config v9 was ACKed at 07:19:37 UTC. Three independent checks around 11:38 UTC confirmed advancing normal frame counters and timestamps. The first resumed image timestamp is unknown. Preserve the original M2/seven-day observer data without exclusions; healthy server status alone does not establish continuous normal image capture.

Webhook, video upload, camera-aware management, and tracking have server implementations. Notification delivery, ESP-side short clips, multiple physical cameras, and tracking still need real-device validation. After the foundations pass, plan these as separate Issues. NAS/Drive/S3, Tapo integration, and moving hardware remain future work requiring explicit interface and operational decisions.
