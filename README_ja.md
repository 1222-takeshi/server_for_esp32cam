# ESP32マルチカメラシステム (ML・I/O制御対応ポテンシャル)

このプロジェクトは、複数のESP32カメラからの画像を中央のWebサーバーに表示できる多機能なシステムの構築を目指しています。画像表示に加えて、機械学習ベースの物体認識を統合し、ESP32カメラに接続されたモーターやその他のI/Oデバイスの制御も可能にすることを構想しています。

現在、サーバーは単一ソースからの画像の受信と表示をサポートしています。将来の開発では、これを複数のカメラフィードに対応できるように拡張し、ML処理パイプラインを実装し、I/O制御のための通信チャネルを確立することに焦点を当てます。

**コア機能 (現状および計画中):**

*   **画像集約:**
    *   ESP32-CAMデバイスからアップロードされた画像を受信・保存します (現在は単一、複数対応を計画中)。
    *   アップロードされた画像を一覧表示・閲覧するためのWebインターフェースを提供します。
*   **複数カメラサポート (計画中):**
    *   様々なESP32カメラからのフィードを識別・管理するメカニズム。
    *   複数のカメラビューを表示するためのユーザーインターフェースの強化。
*   **機械学習統合 (計画中):**
    *   物体検出などのタスクのために、OpenCVや他のMLフレームワークを使用したサーバーサイドでの画像・ストリーム処理。
    *   カメラフィードと並べて認識結果を表示。
*   **リモートI/O制御 (計画中):**
    *   モーターやその他の周辺機器を作動させるために、サーバーからESP32デバイスへ制御信号を送信するインターフェース。

## ハードウェア要件

このサーバーアプリケーション自体は、標準的なコンピューターまたはサーバー環境 (Windows, Linux, macOS) で動作します。

意図した通りに画像アップロード機能を利用する (例: リモートカメラ設定) ためには、通常以下のものが必要です:

*   **画像キャプチャデバイス:**
    *   **ESP32-CAM:** プロジェクトの文脈から推奨される一般的な選択肢です。このデバイスは、画像をキャプチャし、HTTP POSTリクエストを介してこのサーバーの `/upload` エンドポイントに送信するようにプログラムする必要があります。
    *   **その他のカメラ付きマイクロコントローラー (Wi-Fi対応):** 画像をキャプチャし、HTTPリクエストを作成できる任意のマイクロコントローラー (例: カメラモジュール付きRaspberry Pi、他のESP32バリアント)。
    *   **スマートフォンまたはコンピューター:** テスト目的で画像を送信するためにも使用できます。
*   **ネットワーク接続:** 画像キャプチャデバイスとこのアプリケーションを実行しているサーバーは、同じネットワーク上にあるか、サーバーがデバイスからアクセス可能である必要があります (例: 適切なポートフォワーディングを設定したインターネット経由)。
    *   **複数カメラの場合:** ネットワークが複数の同時画像ストリームを処理するのに十分な帯域幅を持っていることを確認してください。マルチカメラ設定では、サーバーの処理能力とストレージ容量も考慮する必要があります。

## ソフトウェア要件

### サーバーサイド:

*   **Python:** サーバースクリプト (`server.py`) はPythonで書かれています。Python 3.xを推奨します。
*   **Flask:** Webアプリケーションの構築に使用されるPython用のマイクロWebフレームワークです。pipを使用してインストールできます:
    ```bash
    pip install Flask
    ```
*   **オペレーティングシステム:** Pythonを実行できる標準的なオペレーティングシステム (例: Linux, macOS, Windows)。

### クライアントサイド (例: ESP32-CAM):

*   **ESP32-CAMの場合:**
    *   **Arduino IDE** または **PlatformIO IDE:** ESP32-CAMのプログラミング用。
    *   **ESP32 ボードサポートパッケージ:** Arduino IDEまたはPlatformIOにインストールする必要があります。
    *   **関連ライブラリ:** ESP32-CAMで使用される特定のコードに応じて、カメラ操作 (例: `esp_camera.h`)、Wi-Fi接続 (例: `WiFi.h`)、およびHTTPクライアント機能 (例: `HTTPClient.h` またはカスタム実装) のためのライブラリが必要になります。
*   **その他のデバイスの場合:**
    *   画像をキャプチャし、HTTP POSTリクエストを作成するための適切な開発環境とライブラリ。

### オプション (将来の機能強化: ML、I/O制御など):

*   **OpenCV:** 画像処理や物体検出機能を実装する場合、サーバーサイドでOpenCV (Python版 `opencv-python`) が必要になります。
    ```bash
    pip install opencv-python
    ```
*   **TensorFlow/PyTorch (または他のMLフレームワーク):** より高度な物体検出モデル用。
*   **MQTTクライアントライブラリ (例: Paho-MQTT):** I/O制御やセンサーデータのためにESP32デバイスとの双方向通信にMQTTを使用する場合。
    ```bash
    pip install paho-mqtt
    ```
*   **その他の関連Pythonライブラリ:** I/O制御、センサーデータ処理、または特定のMLタスクに選択された方法に応じて。

## セットアップとインストール

### サーバーサイドのセットアップ:

1.  **リポジトリのクローン (任意):**
    まだの場合は、このリポジトリをローカルマシンにクローンします:
    ```bash
    git clone <repository_url>
    cd <repository_directory>
    ```

2.  **Pythonのインストール:**
    Python 3.xがインストールされていることを確認してください。[python.org](https://www.python.org/) からダウンロードできます。

3.  **仮想環境の作成 (推奨):**
    Pythonプロジェクトには仮想環境を作成することをお勧めします。
    ```bash
    python -m venv venv
    # Windowsの場合
    venv\Scripts\activate
    # macOS/Linuxの場合
    source venv/bin/activate
    ```

4.  **依存関係のインストール:**
    Flask (および後で追加される可能性のある他のPython依存関係) をインストールします:
    ```bash
    pip install Flask
    ```
    将来的に `requirements.txt` ファイルが提供される場合は、すべての依存関係を次のようにインストールできます:
    ```bash
    pip install -r requirements.txt
    ```

5.  **ディレクトリ構造:**
    サーバースクリプト (`script/server.py`) は、アップロードされた画像を保存するために、プロジェクトのベースディレクトリ ( `script/` および `templates/` がある場所) に `uploads` という名前のディレクトリを期待します。サーバー起動時に存在しない場合は自動的に作成されます。

### クライアントサイドのセットアップ (例: Arduino IDEを使用したESP32-CAM):

これは一般的なガイドです。ESP32-CAMボードのバージョンや使用する正確なコードによって詳細は異なる場合があります。

1.  **Arduino IDEのインストール:**
    [arduino.cc](https://www.arduino.cc/) から最新のArduino IDEをダウンロードしてインストールします。

2.  **ESP32ボードサポートの設定:**
    *   Arduino IDEを開きます。
    *   `ファイル > 環境設定` に進みます。
    *   「追加のボードマネージャURL」フィールドに次のURLを追加します:
        ```
        https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json
        ```
    *   「OK」をクリックします。
    *   `ツール > ボード > ボードマネージャ...` に進みます。
    *   「esp32」を検索し、Espressif Systemsによるパッケージをインストールします。

3.  **ESP32-CAMボードの選択:**
    *   `ツール > ボード` に進み、特定のESP32-CAMモデル (例: "AI Thinker ESP32-CAM") を選択します。
    *   ボードの要件に応じて `ツール` の下の他の設定 (例: ポート、書き込み装置) を調整します。

4.  **必要なライブラリのインストール:**
    ESP32-CAMスケッチによっては、以下のライブラリをインストールする必要がある場合があります:
    *   Wi-Fi (`WiFi.h`)
    *   HTTPクライアント (`HTTPClient.h`)
    *   カメラ (`esp_camera.h`)
    ライブラリは `スケッチ > ライブラリをインクルード > ライブラリを管理...` からインストールできます。

5.  **公式ESP32カメラドキュメントの参照:**
    カメラの初期化、設定、および高度な使用方法に関する詳細情報については、公式の `esp32-camera` ドライバリポジトリが非常に貴重なリソースです:
    *   [GitHub上のespressif/esp32-camera](https://github.com/espressif/esp32-camera)
    このリポジトリには、カメラドライバのソースコード、サンプル、および堅牢なクライアントサイドファームウェアの開発に非常に役立つさらなるドキュメントが含まれています。

6.  **ESP32-CAMスケッチのロード:**
    *   ESP32-CAMには、以下の機能を持つArduinoスケッチが必要です:
        1.  カメラを初期化する。
        2.  Wi-Fiネットワークに接続する。
        3.  画像をキャプチャする。
        4.  画像データ (例: JPEG) をHTTP POSTリクエストを介してサーバーの `/upload` エンドポイント (例: `http://<your_server_ip>:8080/upload`) に送信する。
    *   ESP32-CAMからサーバーに画像を送信するための多くのサンプルスケッチがオンラインで入手可能です。サーバーのIPアドレスとポートを指すように適合させる必要があります。

    **サンプルスニペット (概念的 - 画像データ送信用):**
    ```c++
    // ... (WiFi接続とカメラ設定) ...

    #include <HTTPClient.h>

    void sendPhotoToServer(uint8_t *imageData, size_t imageLen) {
      HTTPClient http;
      // <your_server_ip> を server.py を実行しているマシンの実際のIPに置き換えてください
      http.begin("http://<your_server_ip>:8080/upload");
      http.addHeader("Content-Type", "image/jpeg"); // または適切なコンテントタイプ

      int httpResponseCode = http.POST(imageData, imageLen);

      if (httpResponseCode > 0) {
        String response = http.getString();
        Serial.println(httpResponseCode);
        Serial.println(response);
      } else {
        Serial.print("Error on sending POST: ");
        Serial.println(httpResponseCode);
      }
      http.end();
    }

    // メインループまたは関数内:
    // camera_fb_t * fb = esp_camera_fb_get();
    // if (fb) {
    //   sendPhotoToServer(fb->buf, fb->len);
    //   esp_camera_fb_return(fb);
    // }
    ```

7.  **ESP32-CAMへのスケッチのアップロード:**
    ESP32-CAMをコンピューターに接続し (通常はUSB-シリアルアダプター経由で、フラッシュモードになっていることを確認)、スケッチをアップロードします。

## プロジェクトの実行

現在、このプロジェクトは主に単一のESP32-CAMのようなデバイスから画像を受信して表示するサーバーを提供します。「将来の開発 / ロードマップ」セクションで説明されている複数カメラ管理、MLベースの物体認識、リモートI/O制御の機能は計画中の機能強化です。

### 1. サーバーの実行:

*   ターミナルで `script` フォルダを含むディレクトリに移動します。
*   仮想環境を作成した場合は、それがアクティブになっていることを確認してください。
    ```bash
    # Windowsの場合
    # venv\Scripts\activate
    # macOS/Linuxの場合
    # source venv/bin/activate
    ```
*   Flaskサーバーを実行します:
    ```bash
    python script/server.py
    ```
*   デフォルトでは、サーバーは `http://0.0.0.0:8080/` で起動します。これは、ネットワーク上の任意のIPアドレスからポート8080でアクセス可能であることを意味します。
*   ターミナルにサーバーが実行中であることを示す出力が表示されます (類似の形式):
    ```
     * Serving Flask app 'server'
     * Debug mode: off
     * Running on all addresses (0.0.0.0)
     * Running on http://127.0.0.1:8080
     * Running on http://<your_local_ip>:8080
    Press CTRL+C to quit
    ```
    同じネットワーク上の別のデバイス (ESP32-CAMなど) からサーバーにアクセスする場合は、`<your_local_ip>` をメモしておきます。

### 2. クライアントの設定と実行 (例: ESP32-CAM):

*   クライアントデバイス (例: ESP32-CAM) が以下のようにプログラムされていることを確認してください:
    *   サーバーと同じWi-Fiネットワークに接続する。
    *   画像をキャプチャする。
    *   これらの画像をHTTP POSTリクエストとしてサーバーの `/upload` エンドポイントに送信する。URLは `http://<server_ip_address>:8080/upload` となり、`<server_ip_address>` は `server.py` を実行しているマシンのIPアドレスです。
*   ESP32-CAMまたは他のクライアントデバイスの電源を入れて実行します。

### 3. アップロードされた画像へのアクセス:

*   クライアントから画像がアップロードされると、Webブラウザで次のURLに移動して表示できます:
    `http://<server_ip_address>:8080/files`
*   このページには、正常にアップロードされたすべての画像ファイルが一覧表示されます。ファイル名をクリックすると画像が表示されます。
*   アップロードされた画像は、サーバーのプロジェクトルートフォルダ内の `uploads` ディレクトリに保存されます。

### 将来の機能強化 (マルチカメラ、ML、I/O制御):

「将来の開発 / ロードマップ」で概説されている機能 (マルチカメラフィード、ML処理、I/O制御など) が実装されると:
*   サーバー (`server.py`) が大幅に強化されるか、新しいコンポーネント/スクリプトが導入される可能性があります。
*   クライアントサイド (ESP32) ファームウェアは、新しい機能をサポートするために対応する更新が必要になります (例: カメラIDの送信、制御コマンドの受信)。
*   これらの高度な機能の設定と実行に関する詳細な手順は、このREADMEの各セクションまたは新しい専用ガイドに追加されます。

## 使用方法

このプロジェクトは、以下の機能を備えたWebサーバーを提供します:

### サーバーエンドポイント:

*   **`GET /`**
    *   **説明:** メインHTMLページ (`templates/index.html`) を表示します。
    *   **使用方法:** Webブラウザで `http://<server_ip>:8080/` を開きます。
    *   **レスポンス:** アップロードされたファイルを表示するためのリンクがあるHTMLページ。

*   **`POST /upload`**
    *   **説明:** 画像ファイルをアップロードするためのエンドポイント。サーバーはリクエストボディに生の画像データを期待します。
    *   **使用方法 (プログラム的、例: ESP32-CAMまたはスクリプトから):**
        画像データをボディに入れてHTTP POSTリクエストを送信します。
        *   **メソッド:** `POST`
        *   **URL:** `http://<server_ip>:8080/upload`
        *   **ヘッダー (例):** `Content-Type: image/jpeg` (または画像形式に応じて `image/png` など)
        *   **ボディ:** 画像の生のバイナリデータ。
    *   **レスポンス (成功時):**
        *   **ステータスコード:** `200 OK`
        *   **ボディ (JSON):** `{"message": "File uploaded successfully"}`
    *   **レスポンス (失敗時):**
        *   **ステータスコード:** `400 Bad Request` (例: データなし) または `500 Internal Server Error`。
        *   **ボディ (JSON):** `{"message": "File upload failed", "error": "<error_details>"}`
    *   **注意:** アップロードされたファイルは、サーバーの `uploads/` ディレクトリに `image_<timestamp>.jpg` のようなファイル名で保存されます。

*   **`GET /files`**
    *   **説明:** `uploads/` ディレクトリ内のすべてのファイルを一覧表示するHTMLページ (`templates/files.html`) を表示します。
    *   **使用方法:** Webブラウザで `http://<server_ip>:8080/files` を開きます。
    *   **レスポンス:** クリック可能なファイル名のリストがあるHTMLページ。

*   **`GET /files/<filename>`**
    *   **説明:** `uploads/` ディレクトリから特定のファイルを配信します。
    *   **使用方法:**
        *   通常は `/files` ページ上のリンクをクリックしてアクセスします。
        *   または、Webブラウザで直接 `http://<server_ip>:8080/files/<filename_to_view>` を介してアクセスします。
    *   **レスポンス:** 要求された画像ファイル。

### Webインターフェース:

1.  **メインページ (`/`):**
    *   「アップロードされたファイルを表示」というリンクがある開始点を提供します。

2.  **アップロードされたファイルページ (`/files`):**
    *   サーバーに正常にアップロードされたすべての画像を一覧表示します。
    *   各ファイル名はリンクになっており、クリックすると対応する画像が表示されます。

### サンプルワークフロー (ESP32-CAMからサーバーへ):

1.  **ESP32-CAM:** 画像をキャプチャします。
2.  **ESP32-CAM:** Wi-Fiに接続します。
3.  **ESP32-CAM:** HTTP POSTリクエストを介して画像データを `http://<server_ip>:8080/upload` に送信します。
4.  **サーバー:** データを受信し、`uploads/image_<timestamp>.jpg` として保存し、成功メッセージで応答します。
5.  **ユーザー:** ブラウザで `http://<server_ip>:8080/files` を開き、アップロードされた画像のリストを表示します。
6.  **ユーザー:** 画像ファイル名をクリックして表示します。

## トラブルシューティング

発生する可能性のある一般的な問題と解決策を以下に示します:

### サーバーサイドの問題:

*   **問題:** サーバーが起動しない、または `ImportError: No module named flask`。
    *   **解決策:** Python環境にFlaskがインストールされていることを確認してください。仮想環境を使用している場合は、それがアクティブになっていることを確認してください。`pip install Flask` を実行します。

*   **問題:** `OSError: [Errno 98] Address already in use` (または類似のエラー)。
    *   **解決策:** ポート8080が他のアプリケーションによって既に使用されています。
        *   ポートを使用している他のアプリケーションを停止します。
        *   または、`server.py` を変更して別のポートを使用します: `app.run(host='0.0.0.0', port=8080)` を `app.run(host='0.0.0.0', port=<new_port_number>)` に変更し、クライアントサイドも同様に更新します。

*   **問題:** サーバーは実行されていますが、クライアント (例: ESP32-CAM) が接続できません。
    *   **確認事項:**
        *   **ファイアウォール:** サーバーマシンのファイアウォールがポート8080 (または使用しているポート) への着信接続をブロックしていないことを確認してください。
        *   **IPアドレス:** クライアントの設定でサーバーマシンの正しいIPアドレスを使用していることを確認してください。クライアントが別のデバイスの場合は、サーバーのローカルネットワークIP (例: `192.168.1.x`) を使用し、`127.0.0.1` や `localhost` は使用しないでください。
        *   **ネットワーク:** サーバーとクライアントが同じWi-Fiネットワーク上にあることを確認してください。
        *   **サーバーログ:** クライアントが接続またはアップロードを試みたときに、`server.py` のコンソール出力にエラーメッセージがないか確認してください。

*   **問題:** ファイルはアップロードされますが、画像が破損しているか、期待したものではありません。
    *   **確認事項:**
        *   **クライアントサイドのコード:** クライアントが画像データを正しく送信していることを確認してください (例: 正しい画像形式、完全なデータ)。
        *   **Content-Type ヘッダー:** 現在の `server.py` は保存のために `Content-Type` を厳密には強制しませんが、クライアントが適切なヘッダー (例: `image/jpeg`) を送信していることを確認してください (これは良い習慣です)。サーバーは生のボディを保存するため、クライアントは有効な画像データを送信する必要があります。
        *   **ファイル命名/保存:** サーバーはファイルを `image_<timestamp>.jpg` として保存します。クライアントがJPEG以外のデータを送信した場合でも、ファイル拡張子は `.jpg` になりますが、内容は正しくない可能性があります。

*   **問題:** `uploads` ディレクトリが見つからない、または権限の問題。
    *   **解決策:** `server.py` スクリプトは `uploads` ディレクトリが存在しない場合に作成しようとします。権限のために失敗する場合は、プロジェクトのルートフォルダに手動で `uploads` ディレクトリを作成し、スクリプトを実行しているユーザーが書き込み権限を持っていることを確認してください。

### クライアントサイドの問題 (ESP32-CAMの例):

*   **問題:** ESP32-CAMがWi-Fiに接続できません。
    *   **確認事項:**
        *   **認証情報:** ESP32-CAMスケッチ内のWi-Fi SSIDとパスワードを再確認してください。
        *   **信号強度:** ESP32-CAMが良好なWi-Fi信号を受信していることを確認してください。
        *   **ルーター設定:** 一部のルーターには、新しいデバイスの接続を妨げるMACフィルタリングやその他のセキュリティ設定がある場合があります。

*   **問題:** ESP32-CAMはWi-Fiに接続しますが、サーバーへの画像の送信に失敗します。
    *   **確認事項:**
        *   **サーバーIPとポート:** ESP32-CAMスケッチ内のサーバーIPアドレスとポートが正しく、実行中のサーバーと一致していることを確認してください。
        *   **HTTP POSTリクエスト形式:** スケッチがHTTP POSTリクエストを正しく作成していることを確認してください (正しいエンドポイント `/upload`、正しいヘッダー、ボディ内の画像データ)。
        *   **シリアルモニター:** Arduino IDEのシリアルモニターを使用して、ESP32-CAMスケッチからのエラーメッセージやデバッグ出力を確認してください。これはクライアントサイドの問題を診断するために不可欠です。
        *   **サーバーログ:** ESP32-CAMがアップロードを試みたときに、`server.py` のコンソール出力にメッセージがないか同時に確認してください。

*   **問題:** ESP32-CAMでの画像キャプチャが失敗します。
    *   **確認事項:**
        *   **カメラモデル:** ESP32-CAMスケッチで正しいカメラモデルが選択されていることを確認してください (例: `CAMERA_MODEL_AI_THINKER`)。
        *   **カメラ接続:** カメラモジュールがESP32ボードに正しく接続されていることを確認してください。
        *   **電源:** ESP32-CAMは、特にWi-Fiがアクティブな場合、電力を大量に消費する可能性があります。安定した十分な電源が供給されていることを確認してください (例: 5V、一部のセットアップでは最低2Aを推奨)。電力不足はクラッシュやブラウンアウトを引き起こす可能性があります。
        *   **GPIOピン:** カメラやSDカードに特定のGPIOが必要なボードを使用している場合は、それらが正しく設定され、競合していないことを確認してください。

*   **公式リソースの参照:** ESP32カメラドライバ、カメラの初期化、またはカメラコンポーネントからの特定のエラーコードに関連する問題については、[公式esp32-cameraリポジトリのissues](https://github.com/espressif/esp32-camera/issues)およびドキュメントを確認してください。

### 一般的なヒント:

*   **シンプルに始める:** 問題が発生した場合は、問題を切り分けてみてください。まず `curl` や Postman のようなツールでサーバーの機能をテストします。次に、クライアントのWi-Fi接続を個別にテストします。
*   **ログの確認:** 常に `server.py` のコンソール出力とクライアントデバイス (該当する場合) のシリアルモニター出力を確認してエラーメッセージを探してください。
*   **段階的な開発:** クライアントコード (ESP32-CAM用など) を記述する際は、機能を段階的に追加してください (Wi-Fiに接続し、次に簡単なGETリクエストを試し、次にデータをPOSTしてみるなど)。

## コントリビューション

このプロジェクトへのコントリビューションを歓迎します！コントリビュートしたい場合は、以下の一般的なガイドラインに従ってください:

1.  **リポジトリのフォーク:**
    まず、メインリポジトリを自分のGitHubアカウントにフォークします。

2.  **ブランチの作成:**
    フォークしたリポジトリに、機能追加またはバグ修正用の新しいブランチを作成します。説明的なブランチ名を使用してください (例: `feat/add-image-filtering` または `fix/upload-error-handling`)。
    ```bash
    git checkout -b feat/your-new-feature
    ```

3.  **変更の実施:**
    機能またはバグ修正を実装します。
    *   コードが既存のスタイルと構造に従っていることを確認してください。
    *   新しい機能を追加する場合は、関連するドキュメントや例を追加することを検討してください。
    *   新しいPythonの依存関係を追加する場合は、`requirements.txt` (存在する場合、または作成を検討) を更新してください。

4.  **変更のテスト:**
    変更が期待どおりに機能し、新しい問題が発生しないことを確認するために、変更を徹底的にテストしてください。
    *   該当する場合は、新しい機能の単体テストを作成してください。

5.  **変更のコミット:**
    明確で簡潔なコミットメッセージで変更をコミットします。
    ```bash
    git add .
    git commit -m "feat: Add feature X"
    # または "fix: Resolve bug Y"
    ```

6.  **フォークへのプッシュ:**
    変更をフォークしたリポジトリにプッシュします。
    ```bash
    git push origin feat/your-new-feature
    ```

7.  **プルリクエストのオープン:**
    元のリポジトリに移動し、フォークしたブランチから元のリポジトリの `main` ブランチへのプルリクエスト (PR) をオープンします。
    *   PRに変更の明確な説明を記載してください。
    *   関連するissueを参照してください (例: "Closes #123")。

8.  **コードレビュー:**
    PRがレビューされ、フィードバックが提供される場合があります。要求された場合は、さらなる変更を行う準備をしてください。

コントリビュートすることにより、あなたのコントリビューションがプロジェクトのライセンスの下でライセンスされることに同意するものとします。

## 将来の開発 / ロードマップ

このプロジェクトは現在初期段階にあり、単一クライアントからの基本的な画像アップロードに焦点を当てています。長期的なビジョンには、これを高度な機能を備えた包括的なマルチカメラ管理システムに進化させることが含まれます。将来の開発で計画されている主な分野は次のとおりです:

### 1. 強化されたマルチカメラサポート:

*   **カメラ識別と管理:**
    *   各ESP32-CAMクライアントを一意に識別するためのシステムを実装します (例: MACアドレス、設定可能なID)。
    *   複数の識別されたカメラからのストリーム/画像を処理および区別するためのサーバーサイドロジック。
*   **動的Webインターフェース:**
    *   複数のカメラからのフィードを同時に表示できるWeb UIを開発します (例: グリッドビュー、選択可能なフィード)。
    *   ユーザーが個々のカメラフィードにラベルを付けたり名前を付けたりできるようにします。
*   **スケーラブルなストレージ:**
    *   保存された画像を特定のカメラに簡単に帰属できる方法で整理します (例: カメラIDごとのサブディレクトリ)。

### 2. 機械学習統合:

*   **サーバーサイドの物体検出/認識:**
    *   基本的な画像処理タスク (例: モーション検出、顔検出) のためにOpenCVを統合します。
    *   物体認識 (例: 一般的な物体、人物、特定のアイテムの識別) のために、事前学習済みまたはカスタムモデルを使用して、より高度なMLフレームワーク (TensorFlow, PyTorch) の使用を検討します。
    *   受信した画像/ストリームを処理し、結果を保存/表示するためのパイプラインを開発します。
*   **リアルタイムアラートと通知:**
    *   ML検出結果に基づいて、特定のイベントに対するアラート (例: メール、Web通知) を送信するシステムを実装します。
*   **データ注釈とトレーニング (長期):**
    *   カスタムMLモデルをトレーニングするために画像を収集および注釈付けする機能を検討します。

### 3. リモートI/O制御とセンサー統合:

*   **双方向通信:**
    *   サーバーからESP32クライアントにコマンドを送信するための堅牢な通信チャネル (例: MQTT、WebSockets、または専用HTTPエンドポイント) を確立します。
*   **モーター制御インターフェース:**
    *   接続されたESP32デバイスでモーターの動きをトリガーするためのサーバーサイドUI要素とAPIエンドポイントを開発します (例: パンチルトカメラマウント、ロボットコンポーネント)。
    *   コマンドを解釈し、モーターを作動させるためのESP32ファームウェア (例: PWM、モータードライバー経由)。
*   **センサーデータ収集:**
    *   ESP32クライアントがセンサーデータ (例: 温度、湿度、モーションセンサー) をサーバーに送信できるようにします。
    *   カメラフィードと並べて、またはダッシュボードにセンサーデータを表示します。

### 4. システム改善:

*   **セキュリティ:** ユーザー認証、安全な通信 (HTTPS)、およびフィードや制御機能へのアクセスに対する承認を実装します。
*   **設定:** UIまたは設定ファイル (例: カメラ設定、ストレージパス、MLモデル選択) を介してより多くの設定を構成できるようにします。
*   **パフォーマンスとスケーラビリティ:** 複数の同時ストリームと大量のデータを処理するためにサーバーのパフォーマンスを最適化します。
*   **ユーザーインターフェース/ユーザーエクスペリエンス:** 情報の使いやすさと表示を向上させるためにWebインターフェースを継続的に改善します。
*   **包括的なAPI:** サーバーとのプログラムによる対話のための十分に文書化されたAPIを開発します。

これらの分野でのコントリビューションを強く歓迎します。ガイドラインについては、「コントリビューション」セクションを参照してください。
